# 나만의 재분배 시뮬레이터 (웹판)

테일즈위버의 스탯 재분배 플래너 '나만의 재분배 시뮬레이터'를 브라우저에서 쓰는 판입니다.
레벨업하며 스탯 포인트를 찍어 육성 계획을 만들고, 그 계획을 재분배 로그와 육성 가이드로 나눕니다.
원작은 rugumaxi가 2015년에 공개한 Flash판입니다(맨 아래 '원작자의 공개 안내문'). 2026년에 한국어로 옮기고 버그를 고친 뒤 브라우저에서 돌도록
계산을 그대로 옮겼습니다. Flash판을 헤드리스로 돌린 결과와 조작마다 자동으로 비교해, 같은 조작이면 같은 스탯·재분배 로그·육성 가이드가 나오는 것을
확인했습니다(2026년 11월에 Flash판은 저장소에서 지웠고, 그 비교 결과를 시험의 정답으로 남겼습니다).
설치도 로그인도 없고, 계획은 서버가 아니라 쓰는 사람의 브라우저에만 남습니다.

## 쓰는 법

- 캐릭터와 타입을 고릅니다(넓은 화면은 왼쪽 목록, 좁은 화면은 위쪽의 캐릭터 단추).
- **레벨업**(`L`)과 스탯 **+1**(`S` `H` `I` `F` `M` `X` `A` = STAB HACK INT DEF MR DEX AGI)로 계획을 만듭니다.
  `Shift`+스탯 키(또는 스탯마다 있는 대시 단추)는 그 스탯을 비용이 오르기 전까지 몰아 찍고, 포인트가 모자라면 레벨업하며 찍습니다.
  대시가 끝나는 값은 단추에 'N까지'로 보입니다.
- `←`/`→`는 되돌리기/다시 실행입니다. `Shift`를 함께 누르면 대시 단위로 움직입니다(같은 스탯을 같은 비용으로 이어 찍은 조작을
  사이의 레벨업과 함께 한꺼번에).
- 보너스%(다음 레벨업부터 적용)와 주력 계열을 고릅니다. **스탯 편집**(`T`)으로 지금 캐릭터의 상태에서 계획을 시작할 수 있습니다.
- **재분배 로그**와 **육성 가이드** 탭(`G`로 전환)의 글을 '복사'하거나, **링크 복사**로 계획 전체를 링크 하나에 담아 나눕니다.
- 받은 재분배 로그는 '붙여넣은 로그' 칸에 붙여넣고 **로그 불러오기**(`P`)를 누릅니다. 지금 계획이 지워지게 되면 먼저 묻습니다.
  일본어판(원작)에서 만든 로그는 캐릭터·계열 이름이 달라 제대로 읽히지 않습니다(불러오기 전에 알려 줍니다).
- 2026년 11월 판부터 최고 레벨과 스탯 상한이 255이고, 타입 이름(예: `베기` → `베기형`, 이자크는 `무술형`·`기공형`·`반격형`)과 일부 캐릭터의
  기본 스탯·필요 포인트가 바뀌었습니다. 그전 판에서 만든 로그·링크·자동 저장도 이 판의 계획으로 읽습니다. 이름이 바뀐 타입은 그 캐릭터의
  첫 타입으로, 255를 넘는 LV와 스탯(상한이 285이던 때의 계획)은 255로 읽고, 화면이 그렇다고 알려 줍니다. 255를 넘게 찍었던 포인트는 쓰지 않은 채
  남습니다. LV 255를 넘어 간 계획은 LV 255에서 멈추고, 그 뒤 레벨에서 찍은 스탯은 포인트가 남는 만큼만 LV 255에서 찍습니다.
  타입을 알아보지 못한 붙여넣은 로그는 칸에 남으니, 끝의 캐릭터/타입 줄을 새 이름(예: `루시안/베기형`)으로 고쳐 다시 불러오면 됩니다.
- 계획은 이 브라우저에 자동으로 저장되어 다시 열면 이어집니다(되돌리기 기록까지). `?`를 누르면 단축키 목록이 나옵니다.

## 개인정보

- 계산은 모두 브라우저 안에서 합니다. 서버에 저장하는 것은 없습니다.
- 자동 저장은 이 브라우저의 저장소(localStorage: 계획 `oresim:plan`, 효과음 설정)에만 남습니다. 다른 기기나 브라우저와 맞추지 않고,
  브라우저의 사이트 데이터를 지우면 사라집니다.
- 공유 링크는 계획 전체를 주소의 `#` 뒤에 담습니다. 브라우저는 `#` 뒤를 서버로 보내지 않으므로, 이 페이지를 내보내는 서버와 Cloudflare 같은 중간
  서비스도 링크 속 계획을 받지 않습니다. 링크를 받은 사람과 링크를 옮긴 메신저는 그 내용을 볼 수 있습니다.
- 페이지는 글꼴을 Google Fonts(fonts.googleapis.com, fonts.gstatic.com)에서 받습니다. 그 밖에 분석·광고·추적 요청은 없습니다.
  웹 서버와 호스팅은 여느 사이트처럼 접속 기록(IP 주소, 요청한 파일)을 남길 수 있습니다.

## 내 컴퓨터에서 열기

- `public/index.html`을 브라우저로 열면 됩니다(`file://`). 모든 기능이 돌고, 효과음만 다른 방식(`<audio>`)으로 냅니다.
  이렇게 연 페이지에서 만든 공유 링크는 그 컴퓨터의 파일을 가리키므로, 남에게 줄 링크는 웹에 올린 주소에서 만듭니다.
- 또는 [Node.js](https://nodejs.org/) 22 이상이 있으면 저장소 맨 위에서 `npm start`(= `node tools/serve.js`)를 돌리고 http://localhost:8000/ 을 엽니다.
  `node tools/serve.js --port 8080`으로 포트를, `--host 0.0.0.0`으로 같은 네트워크의 휴대폰에서도 열 수 있게 합니다.
  이 서버는 고친 파일이 바로 보이게 만든 작은 확인용 서버입니다. 사이트로 내보낼 때는 아래처럼 올립니다.
- Chromium 계열 브라우저로 시험했습니다. 다른 브라우저(특히 Safari)는 시험하지 못했습니다.

## 웹에 올리기

### 어떻게 도는가

이 사이트는 **정적 파일**(HTML, CSS, 자바스크립트, 그림, 효과음)뿐입니다. 방문자의 브라우저가 이 파일들을 받아 그 안에서 모든 계산을 합니다.
서버가 하는 일은 파일을 내려 주는 것뿐이라 서버 프로그램도, 데이터베이스도, 빌드도 필요 없습니다.

```
방문자 브라우저 ── https://oresim.example.com/ ──▶ DNS(도메인 → 서버 주소) ──▶ 웹 서버(Apache·nginx·정적 호스팅)
                                                                                └ 웹 루트 폴더의 파일을 그대로 내려 준다
                                                                                  (= 이 저장소의 public/ 내용)
```

그래서 할 일은 둘입니다.

1. `public/`의 **내용**(`index.html`, `app.css`, `favicon.svg`, `js/`, `img/`, `se/`)을 웹 서버가 내보내는 폴더(웹 루트)에 올린다.
   주소가 모두 상대경로라 도메인 맨 위(`https://oresim.example.com/`)든 하위 폴더(`https://example.com/oresim/`)든 됩니다.
2. 도메인이 그 서버를 가리키게 하고 **HTTPS**를 켠다. 복사·붙여넣기 단추가 쓰는 클립보드는 HTTPS 페이지에서만 열립니다.

가지고 있는 것에 따라 아래 셋 가운데 하나를 고르면 됩니다.

### (1) 웹 호스팅(공유 호스팅, FTP로 파일을 올리는 곳)

카페24·가비아 같은 웹 호스팅은 대개 Apache입니다.

1. 호스팅 관리 화면에서 도메인을 연결합니다(도메인을 같은 회사에서 샀으면 보통 이미 연결되어 있습니다).
2. FTP(또는 SFTP) 프로그램(FileZilla 등)으로 접속해 웹 루트 폴더(호스팅마다 `www`, `public_html`, `html` 등)에 `public/`의 내용을 올립니다.
3. `deploy/apache.htaccess`를 같은 폴더에 `.htaccess`라는 이름으로 올립니다. 캐시와 문자 코드(UTF-8)를 맞추고 `http://`를 `https://`로 넘깁니다.
   호스팅이 `.htaccess`를 허용하지 않아도 페이지는 돕니다.
4. 관리 화면에서 무료 SSL(HTTPS)을 켭니다.

### (2) 내 서버(VPS 등)에 nginx

1. 서버에 `public/`의 내용을 복사합니다. 예: `rsync -a --delete public/ 서버:/var/www/oresim/`
2. `deploy/nginx.conf`를 서버의 nginx 설정 폴더(예: `/etc/nginx/sites-available/oresim`)에 복사해 도메인과 경로를 고치고 켭니다
   (`nginx -t`로 확인한 뒤 `systemctl reload nginx`).
3. 도메인의 DNS에 A 레코드(서버의 IP 주소)를 더하고, [Let's Encrypt](https://letsencrypt.org/)(certbot)로 인증서를 받습니다.

### (3) 정적 호스팅 서비스

Cloudflare Pages, Netlify처럼 저장소나 폴더를 올리면 내보내 주는 서비스도 됩니다. 빌드 명령은 비우고 내보낼 폴더(출력 폴더)를 `public`으로
지정한 뒤, 서비스의 설정에서 내 도메인을 연결합니다. HTTPS는 서비스가 켜 줍니다.

### 캐시와 새 판 올리기

- `index.html`은 캐시하지 않고(`no-cache`: 매번 새 판인지 확인), `index.html`이 `?v=` 판 번호를 붙여 부르는 `app.css`, `js/*.js`, `favicon.svg`는
  오래 캐시해도 됩니다. `deploy/`의 두 설정이 그렇게 합니다. `img/`, `se/`에는 판 번호가 없어 하루만 캐시합니다.
- 새 판은 모든 파일을 덮어써 올립니다. 판마다 `index.html`의 `?v=`가 올라가므로 방문자는 새 파일을 받습니다.
  CDN(Cloudflare 등)을 쓰면 `img/`, `se/`의 파일을 바꾼 판에서 캐시를 비웁니다.
- 엔진이나 표가 바뀐 판을 올리면, 방문자 브라우저에 자동 저장된 계획은 재분배 로그에서 다시 만들어지고 되돌리기 기록은 이어지지 않습니다
  (화면에 알림이 뜹니다).

### Cloudflare를 앞에 둘 때

- **연결**: 프록시된 DNS 레코드(주황 구름)가 서버의 공인 IP를 가리키게 하고 SSL/TLS 모드를 `Full (strict)`로 두거나(원 서버에 유효한 인증서),
  Cloudflare Tunnel(`cloudflared`)로 서버 안의 `http://127.0.0.1:8080`에 잇습니다(`deploy/nginx.conf`의 (나)). 터널은 서버에 들어오는 포트를 열지 않아도 됩니다.
- **Always Use HTTPS**를 켜 둡니다.
- **Rocket Loader**는 이 페이지에서 끕니다. 페이지의 스크립트를 고쳐 써서 나중에 실행하는 기능이라, 표·엔진·화면 스크립트를 차례로 읽고 바로 시작하는
  이 페이지의 순서와 시점이 달라집니다(켠 채로는 시험하지 않았습니다).
- **Cloudflare Access**로 이 주소를 막지 않습니다(막으면 플레이어가 로그인 화면을 만납니다). 혼자 쓰려는 경우에만 씁니다.
- Web Analytics 자동 설정처럼 HTML에 스크립트를 끼워 넣는 기능을 켜면 위 '개인정보'의 설명(외부 요청은 Google Fonts뿐)이 달라집니다.

## 개발

- 구성: `public/`(사이트), `data/tables.json`(캐릭터·타입·계열·레벨업 POINT 표의 원본, 설명은 `data/README.md`), `tools/`(표 생성기, 확인용 서버),
  `tests/`(시험, 설명은 `tests/README.md`), `deploy/`(웹 서버 설정 예). npm 패키지는 쓰지 않습니다(의존성 0, Node.js 22).
- 표를 고칠 때: `data/tables.json`을 고치고 `npm run gen`(= `node tools/gen-const.js`)으로 `public/js/const.js`를 다시 만든 뒤 `npm test`를 돌립니다.
  `const.js`는 손으로 고치지 않습니다.
- 시험: `npm test`(표 확인, 엔진의 정답 기록, 불변식), `npm run test:web`(브라우저 화면 시험. [Playwright](https://playwright.dev/)가 있어야 돌고,
  없으면 건너뜁니다: `npm install --no-save playwright && npx playwright install chromium`).
