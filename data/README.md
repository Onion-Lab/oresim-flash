# data — 표의 원본

`tables.json`이 시뮬레이터가 쓰는 모든 표(캐릭터·타입의 기본 스탯과 필요 포인트, 계열, 레벨업 POINT, 상한)의 원본이다.
고친 뒤 저장소 맨 위에서 `npm run gen`(= `node tools/gen-const.js`)으로 `public/js/const.js`를 다시 만들고 `npm test`를 돌린다.
`const.js`는 엔진이 읽는 모양(캐릭터·타입·계열 번호로 찾는 병렬 배열 `Oresim.CONST`)으로 펼친 자동 생성 파일이라 손으로 고치지 않는다.
생성기는 모양이 틀린 표(칸 수, 없는 계열 이름, 0 이상의 정수가 아닌 값, 모르는 키 등)를 받지 않고 까닭을 모두 알린다.
이름 규칙(아래)은 `tests/const-check.js`가 본다.

스탯 순서는 어디서나 `STAB, HACK, INT, DEF, MR, DEX, AGI`(0~6)이고, 칸이 11개인 곳은 그 뒤에 `HP, MP, SP, WEIGHT`(7~10)가 온다.
WEIGHT 는 원본에서 주석 처리되어 계산에 쓰이지 않는다(칸과 값만 남아 있다).

| 키 | 뜻 |
|---|---|
| `maxLevel` | 최고 레벨(지금 255) |
| `maxStatus` | 상한 11칸: 스탯 일곱(지금 255), HP, MP, SP, WEIGHT |
| `statusName` | 스탯 이름 12개(마지막 둘은 WEIGHT, POINT). 로그 글에 그대로 쓰이므로 바꾸면 옛 로그를 읽지 못한다 |
| `statusUp` | 스탯 1포인트마다 오르는 `[HP, MP, SP, WEIGHT]` |
| `bonusStatusPoint` | n번째 값 = LV n이 될 때 얻는 POINT. 꼭 `maxLevel`칸(한 줄에 10칸씩 적었다: 줄 k는 LV 10k+1 ~ 10k+10) |
| `xien` | 계열 50칸(번호 0~49 = 계열 번호. 로그 형식이 50칸을 전제한다). 칸마다 `name`(이름. 이름 없는 칸은 쓰지 않는 자리이고 이름 있는 칸 뒤에만 온다), `upBonus`(레벨업마다 확정으로 오르는 11칸. HP/MP/SP 칸은 평균), `randomUpBonus`(보너스를 받을 때 오르는 스탯 7칸), `minUpStatus`·`maxUpStatus`(레벨업의 `[HP, MP, SP, WEIGHT]` 상승 범위) |
| `characters` | 캐릭터. 순서가 캐릭터 번호다(화면 목록 순서). 아래 |
| `unusedSlots` | 화면에 없는 캐릭터 자리 넷(16~19번). 쓰이지 않지만 지우면 표 지문이 바뀌어 방문자의 자동 저장이 로그에서 다시 만들어지므로 남겨 두었다 |

캐릭터 하나:

```json
{
  "name": "루시안",
  "types": [
    { "name": "물리복합", "status": [4, 3, 1, 2, 1, 2, 2, 220, 50, 1000, 1100], "needPoint": [1, 1, 3, 2, 3, 2, 2], "xien": "도계 HACK/DEF" }
  ],
  "maxXien": {
    "검계 STAB/DEX": [3, 5, 8, 10]
  }
}
```

- `types`: 타입 1~3개(순서가 타입 번호. 캐릭터를 바꾸면 타입 0으로 시작한다).
  - `status`: 처음 스탯 11칸(스탯 일곱, HP, MP, SP, WEIGHT)
  - `needPoint`: 스탯마다의 처음 필요 포인트 7칸. 스탯 +1 비용은 `needPoint[i] + floor((LV + 5 × 스탯값) / 125)`
  - `xien`: 처음 주력 계열(계열 이름. 이름 없는 칸은 번호). 그 캐릭터의 `maxXien`에 있는 계열이어야 한다
- `maxXien`: 계열 이름(이름 없는 칸은 번호를 글로, 예: `"38"`) → LV 1부터 그 레벨에서 그 계열이 닿을 수 있는 최대 Xien. 배열이 짧으면 마지막 값을 쓴다.
  적지 않은 계열은 그 캐릭터에게 없는 계열이다. `[99]`는 레벨별 자료가 없어 늘 고를 수 있는 계열(이솔렛·벤야·로아미니)이다.

이름 규칙(로그 읽기가 이름으로 캐릭터·타입·계열을 알아보기 때문):

- 캐릭터·타입 이름에는 공백, `/`, `:`을 넣지 않는다. 한 캐릭터의 타입 이름끼리 한쪽이 다른 쪽의 앞부분이 되면 안 된다.
- 계열 이름은 서로 달라야 하고 `:`을 넣지 않는다. 어떤 계열 이름 뒤에 공백을 붙인 글이 다른 계열 이름의 앞부분이 되어서도 안 된다.
- 화면 배치(옆 목록의 타입 줄, 주력 계열 줄)는 지금 이름 길이(가장 긴 타입·계열 이름이 한글 4자)로 맞췄다. 더 긴 이름을 넣으면 화면을 확인한다.
- 이름을 바꾸면 옛 이름을 적은 로그·공유 링크·자동 저장은 그 이름을 알아보지 못한다(타입이면 그 캐릭터의 첫 타입으로 읽는다).

표가 바뀌면 `serialize()`의 표 지문이 저절로 달라져, 방문자 브라우저에 자동 저장된 계획은 엔진 상태 대신 저장된 로그에서 다시 만들어진다.
엔진의 정답 기록(`tests/golden/engine.json`)도 표에 묶여 있으므로, 표를 일부러 바꾼 뒤에는 `node tests/engine-golden.js --update`로 다시 만든다
(그 전에 무엇이 달라졌는지 확인한다. `tests/README.md`).
